# リード対応自動化 セットアップ手順書(プロンプトC)

> 対象: セブンセンシズ株式会社 LP のフォーム/診断/資料DLを受け付ける GAS Webアプリの構築
> 使用コード: [form-endpoint.gs](../gas/form-endpoint.gs)
> 所要時間目安: 60〜90分(Calendly連携含む)

---

## 0. 全体像

```
LP (静的HTML)
  └─ fetch で JSON POST
       ↓
GAS ウェブアプリ (form-endpoint.gs)
  ├─ 入口フィルタ: ハニーポット / 3秒未満送信 / 24h重複統合
  ├─ スプレッドシート「leads」へ記録 + 温度判定 (HOT/WARM/COOL)
  ├─ 通知二重化: Slack Webhook + 管理者メール
  └─ 自動返信メール (相談/診断/資料DL の3文面)
```

---

## 1. スプレッドシート作成

1. Google ドライブで新規スプレッドシートを作成。名前は `【7senses】LPリード管理` など分かりやすく。
2. シートは作らなくてよい(スクリプトが初回実行時に `leads` シートとヘッダー行を自動作成)。
3. リード情報=個人情報のため、**共有設定は「制限付き」のまま**、閲覧が必要な社内メンバーのみ個別追加する。

## 2. スクリプト貼り付け

1. スプレッドシートのメニュー「拡張機能 > Apps Script」を開く(コンテナバインド型で作成される。コード内の `SpreadsheetApp.getActiveSpreadsheet()` はこの前提)。
2. 既定の `コード.gs` の中身を全削除し、[form-endpoint.gs](../gas/form-endpoint.gs) の全文を貼り付けて保存。
3. プロジェクト名を `7senses-lp-endpoint` などに変更。
4. 「プロジェクトの設定」で **ランタイムが V8 になっていることを確認**(既定でV8)。

### 2-1. スクリプトプロパティ設定

「プロジェクトの設定 > スクリプト プロパティ > スクリプト プロパティを追加」で以下を登録。

| キー | 値 | 必須 |
|---|---|---|
| `SLACK_WEBHOOK_URL` | 手順4で取得する Webhook URL | 必須 |
| `ADMIN_EMAIL` | 通知先メール(例: y.wakata.linkdesign@gmail.com) | 必須 |
| `CALENDLY_URL` | 手順5で作成する日程調整リンク | 必須 |
| `WHITEPAPER_URL` | 資料PDFの公開リンク(Googleドライブ「リンクを知っている全員」等) | 必須 |
| `BLOG_URL` | ブログトップURL | 任意 |
| `UNSUBSCRIBE_URL` | 配信停止ページURL: `https://<ドメイン>/unsubscribe/`(実装済み。GAS type:"unsubscribe" で unsubscribe シートに記録・確認メール送信) | 推奨 |
| `SLACK_MENTION` | 例 `<@U0123ABCD>`(未設定時は `@channel`) | 任意 |

> SlackのメンバーIDは、Slackで自分のプロフィール →「…」→「メンバーIDをコピー」で取得。

### 2-2. 初回の権限承認

1. エディタで関数 `testDiagnosisSubmission` を選択して「実行」。
2. 権限承認ダイアログが出るので、自分のGoogleアカウントで許可(スプレッドシート・メール送信・外部接続の3権限)。
3. 実行後、シートに `leads` タブとテスト行ができ、Slack・メールが届けば内部処理はOK(`test@example.com` 宛の自動返信は実在しないアドレスなのでバウンスして問題ない。気になる場合は自分のメールに書き換えて実行)。
4. 確認後、テスト行は削除してよい。

## 3. ウェブアプリとしてデプロイ → LPに接続

1. 「デプロイ > 新しいデプロイ > 種類の選択: ウェブアプリ」。
2. 設定:
   - 説明: `v1 初回リリース`
   - **次のユーザーとして実行: 自分**
   - **アクセスできるユーザー: 全員**(匿名POSTを受けるため必須)
3. 「デプロイ」→ 表示された **ウェブアプリURL(`https://script.google.com/macros/s/.../exec`)をコピー**。
4. LP側の JS 定数 `GAS_ENDPOINT` にこのURLを設定。
5. **CORS注意**: GASはCORSヘッダを返さないため、LP側の fetch は以下いずれかで送ること。
   - `mode: 'no-cors'` を付ける(レスポンスは読めないが送信は成功する)
   - または `Content-Type: 'text/plain'` で JSON 文字列を送る(プリフライト回避。GAS側は `e.postData.contents` で受けるので変更不要)
6. **コード修正後の再デプロイは「デプロイを管理 > 編集 > 新バージョン」で行うこと**。「新しいデプロイ」を作るとURLが変わり、LP側の書き換えが必要になる。

## 4. Slack Incoming Webhook 作成

1. https://api.slack.com/apps → 「Create New App > From scratch」。App名 `LPリード通知`、対象ワークスペースを選択。
2. 左メニュー「Incoming Webhooks」→ トグルON。
3. 「Add New Webhook to Workspace」→ 通知先チャンネル(例: `#lp-リード`)を選択して許可。
4. 発行された `https://hooks.slack.com/services/...` をコピーし、スクリプトプロパティ `SLACK_WEBHOOK_URL` に登録。
5. `@channel` メンションを個人宛にしたい場合は `SLACK_MENTION` にメンバーID形式(`<@U…>`)で登録。

## 5. Calendly + Zoom 自動発行連携

1. Calendly アカウント作成(無料プランで可。イベントタイプ1種類まで)。
2. 「イベントタイプ」→ 新規作成: **「無料相談(オンライン30分)」**
   - 所要時間: 30分 / 受付期間: 直近2〜3週間 / バッファ: 前後15分
   - 質問項目に「会社名」「相談したい内容(補助金/システム開発/AIO/MEO)」を追加
3. **Zoom連携**: Calendly「Integrations > Zoom」→ Zoomアカウントで認証 → イベントタイプの「場所」を **Zoom** に設定。これで**予約確定と同時にZoom URLが自動発行**され、双方の確認メールに記載される。
4. リマインダー: Workflows(またはイベント通知設定)で「24時間前」「1時間前」のリマインドメールをON(無断キャンセル対策)。
5. イベントタイプの共有リンク(`https://calendly.com/xxx/30min`)をスクリプトプロパティ `CALENDLY_URL` に登録。

## 6. テスト手順

デプロイURLに対して PowerShell から直接POSTして検証する(`<URL>` は手順3のウェブアプリURL)。

### 6-1. 正常系(3種)

```powershell
# 相談フォーム(本文に「補助金」→ HOT昇格の確認)
$body = @{ type='contact'; name='テスト太郎'; email='自分のメール'; company='テスト社';
  message='補助金を使ってAIを導入したい'; website=''; ts=([DateTimeOffset]::Now.ToUnixTimeMilliseconds()-60000) } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri '<URL>' -ContentType 'text/plain' -Body $body
```

確認: ①シートに行追加(温度=HOT) ②Slack通知に🔥タグ ③管理者メール ④自動返信が届く。
同様に `type='diagnosis'`(diagnosis オブジェクト付き→温度HOT・スコア整形メール)、`type='download'`(温度COOL・DLリンクメール)も確認。

### 6-2. ハニーポット

`website='http://spam.example'` にして送信 → **応答は200だが、シート・Slack・メールいずれも発生しない**ことを確認。

### 6-3. 連投(3秒ルール)

`ts` を現在時刻(`[DateTimeOffset]::Now.ToUnixTimeMilliseconds()`)ちょうどにして送信(経過0秒扱い)→ 破棄されることを確認。LP実機では、ページを開いて即送信 → 弾かれる / 3秒以上待って送信 → 通ることを確認。

### 6-4. 24時間重複統合

1. 同じメールアドレスで `download` → `contact` の順に2回送信。
2. 確認: **シートの行は増えず**、1回目の行の「メモ」列に `[MM/dd HH:mm 再送信: 無料相談] …` が追記され、温度が COOL→HOT(またはWARM)に更新される。
3. Slack通知には「(24h内の再送信・既存行に統合)」と表示される。

### 6-5. 通知二重化の確認

`SLACK_WEBHOOK_URL` を一時的に壊れた値にして送信 → Slackは失敗しても**管理者メールと自動返信は届く**ことを確認(確認後は必ず戻す)。

## 7. 運用チェックリスト

- [ ] HOT リードは当日中、WARM/COOL も3営業日以内に人間が返信(SLA)
- [ ] 自動返信フッターの配信停止依頼(返信 or フォーム)を受けたら、シートのメモ列に「配信停止」と記録し、ステップメール対象から即除外(特定電子メール法)
- [ ] 週1でシートの温度別件数を確認(→ [計測改善90日運用.md](計測改善90日運用.md) の週次運用へ)
- [ ] GASの「実行数」画面でエラーログを週1確認
- [ ] MailApp の送信上限は無料アカウント 100通/日・Workspace 1,500通/日。超過が見えたら Workspace 移行を検討

## トラブルシュート

| 症状 | 原因と対処 |
|---|---|
| LPから送信してもシートに載らない | デプロイ設定「アクセス: 全員」になっているか / 再デプロイでURLが変わっていないか / `ts` をLP側が送っているか |
| Slackだけ来ない | Webhook URL失効(アプリ削除・チャンネル削除)。手順4で再発行 |
| 自動返信が迷惑メール行き | 送信元がgmail.comの場合起きやすい。Google Workspace の独自ドメイン送信 + SPF/DKIM設定を推奨 |
| 「承認が必要」エラー | スコープ追加後は再承認が必要。`testDiagnosisSubmission` を再実行して許可 |
