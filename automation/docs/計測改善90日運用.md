> KPIゴール(90日): 「AI導入補助金」3位以内 / オーガニック2,000/月 / AI経由流入100/月 / CVR 5%超 / リード60件累計([戦略設計書.md](../../戦略設計書.md) §5)

## 1. 初期設定(Day 1-3 で完了させる)

### 1-1. GA4: コンバージョン(キーイベント)登録

1. GA4 管理 > データの表示 > イベント。LPで一度ずつ実イベントを発火させ、一覧に5イベントが出ることを確認(反映まで最大24時間)。
2. 管理 > データの表示 > **キーイベント** > 「新しいキーイベント」で以下を登録:
   - `form_submit`(主CV)
   - `diagnosis_complete`(主CV)
   - `lead_capture`(主CV・重複計上に注意 ※下記)
   - ※ `cta_click` と `scroll_depth` はキーイベントに**しない**(中間指標。CVR が薄まる)
3. **重複計上の扱い**: `lead_capture` は `form_submit`/`diagnosis_complete` と同時発火する設計のため、**対外レポートのCV数は `lead_capture` のみ**を使い、`form_submit {form_type}` / `diagnosis_complete {grade}` は内訳分析用とする。
4. カスタムディメンション登録(管理 > カスタム定義): `percent` / `cta_id` / `form_type` / `grade` / `source` をイベントスコープで登録(登録しないと探索でパラメータ別集計ができない)。

### 1-2. GA4: AI経由流入セグメントの作成

1. 探索(Explore)> 空白 > セグメント「+」> **セッション セグメント**。
2. 条件: `セッションの参照元` → 演算子「**正規表現に一致**」→ 値:

```
.*(chatgpt\.com|perplexity\.ai|gemini\.google\.com|copilot\.microsoft\.com).*
```

3. セグメント名: `AI経由流入`。保存すると同じ探索レポート内で再利用可能。
4. あわせて比較用に `オーガニック検索`(セッションのデフォルトチャネルグループ = Organic Search)セグメントも作成。
5. **注意**: AIチャットからの流入はリファラが落ちて `(direct)` になるケースが多い。この数字は「最低ライン」として扱い、実際のAI経由はこれ以上あると解釈する。ChatGPT等は遷移時に `utm_source=chatgpt.com` を付けることがあるため、`セッションのソース` でも同じ正規表現で拾えるよう両方を条件に入れる(OR条件)。

### 1-3. GSC: AI Overview インプレッションの確認

1. Search Console > 検索パフォーマンス > 「検索での見え方(Search Appearance)」フィルタを開く。
2. 「**AI Overview**(AIによる概要)」の項目が表示されていればそれを選択し、AI Overview 経由の表示回数/クリックを確認できる(データがない期間・プロパティでは項目自体が出ない)。
3. **項目が出ない場合の代替検知**: 掲載順位1〜3位なのにCTRが基準表(§3-2)を大きく下回るクエリは、AI Overview に回答を吸われている可能性が高い。この「高順位×低CTR」クエリを週次でマークし、AI Overview 対策(冒頭断言文・FAQ構造化データ)の対象にする。

### 1-4. その他

- GSC と GA4 を連携(GA4 管理 > プロダクトのリンク > Search Console)。
- Looker Studio で GSC + GA4 を1画面にした無料ダッシュボードを作成(日次レポートの元データ)。
- LP・ブログの全CTAリンクに `cta_id` 命名規則を確定(例: `hero_shindan` / `price_soudan` / `footer_dl`)。**途中で命名を変えない**(時系列比較が壊れる)。

## 2. 日次運用(5分)

### 2-1. Slack統合レポートに含める項目

毎朝、Slackの `#lp-リード` に以下を1メッセージで投稿(手動 or GAS+各APIで自動化。まずは手動でよい):

| 区分 | 項目 |
|---|---|
| GSC | 表示回数 / クリック数 / 「AI導入補助金」「AIOコンサルティング」「MEO対策 大阪」の掲載順位(前日比) |
| GA4 | セッション / 流入チャネル内訳(Organic・Direct・Referral・Social) |
| CV | `lead_capture` 件数(source内訳: contact / diagnosis / download)/ leadsシートの温度別内訳(🔥/🌤/❄️) |
| **AI経由** | **AI経由流入セッション数を独立行で**(chatgpt / perplexity / gemini / copilot 別) |
| AI引用 | 新たにAIに引用された記事があれば記載(下記2-2) |
| アラート | CV 0件が3日続いたら🚨 / 主要KWが5位以上急落したら🚨 |

### 2-2. 「どの記事がどのAIに引用されたか」の追跡方法

1. **リファラ側**: GA4 探索で ディメンション「ページパス」×「セッションの参照元」、セグメント=AI経由流入。→ **どの記事に・どのAIから**着地したかが分かる(例: `/blog/ai-hojokin-towa` × `chatgpt.com`)。
2. **GSC突合**: 同じ記事について GSC のページフィルタで対象クエリを確認し、「AI経由で着地した記事」と「Google側で表示されているクエリ」を突き合わせる。→ どの質問文脈で引用されているかを推定できる。
3. **実地確認**: 引用が観測された記事のテーマを ChatGPT / Perplexity に実際に質問し(例「AI導入に使える補助金は?」)、自社が引用されるか・どの一文が引かれるかを目視確認。引用された一文はスプレッドシート `AI引用ログ`(日付/AI/質問文/引用記事/引用文)に記録する。
4. この記録が **AIOコンサル商材の実演デモ素材**になる(戦略設計書 §1-2 の方針)。

## 3. 週次運用(60分・毎週月曜推奨)

### 3-1. 順位11〜20位記事の抽出 → リライトキュー投入

「2ページ目にいる記事」は最小の労力で1ページ目に上がる最有力候補。

1. GSC > 検索パフォーマンス > 期間「過去28日」> 表示回数・掲載順位を表示。
2. エクスポートしてスプレッドシートで `掲載順位 11〜20 かつ 表示回数 50以上` でフィルタ。
3. 該当クエリ×ページを「リライトキュー」シートに投入(列: クエリ/ページ/順位/表示回数/CTR/施策/期限)。
4. リライトの定石(上から順に効く):
   - 検索意図の再確認: 上位10件の共通要素(見出し・網羅項目)との差分を埋める
   - 冒頭に断言文(「〜とは…である」)+結論を追加(AIO兼用)
   - 一次情報(採択率90%以上・支援50社+・着金2〜3ヶ月・料金)を追記
   - 内部リンク: LP・関連S記事へ双方向で張る
   - 更新日を明示して再公開
5. 1週間のリライトは**2〜3本まで**(新規記事の投下を止めない)。

### 3-2. CTR不足タイトルの改題基準

GSC で `表示回数100以上` のクエリを順位帯別に見て、下表の期待CTRを下回っていたら改題対象。

| 掲載順位 | 期待CTRの目安 | 下回ったときの対応 |
|---|---|---|
| 1〜3位 | 10%以上 | 最優先で改題。1位で10%未満はAI Overview吸収も疑う(§1-3) |
| 4〜6位 | 5%以上 | 改題候補 |
| 7〜10位 | 2%以上 | 改題よりリライト(順位向上)を優先 |
| 11位以下 | — | CTRは見ない(まず順位) |

改題ルール:
- 検索クエリの文言をタイトル前半28文字以内に入れる
- 数字・年号を入れる(「2026年版」「最大350万円」)※根拠のある数字のみ(景表法)
- 改題は**1記事につき1要素ずつ**変更し、2週間観測してから次を変える
- 改題日をリライトキューに記録(効果判定のため)

### 3-3. CTAクリック率・スクロール到達率レポートの見方

GA4 探索で以下の2表を毎週確認:

**① CTA別クリック率**(ディメンション: `cta_id` / 指標: イベント数)
- `cta_click ÷ LP表示回数` を CTA別に算出。
- 見方: **最下部CTAが最多なら正常**(読了者が押す)。ヒーローCTAが極端に低い(0.5%未満)ならファーストビューのコピーか押しやすさに問題 → 月次A/Bテスト(§4-1)の題材にする。

**② スクロール到達ファネル**(ディメンション: `percent` / 指標: イベント数)
- 25% → 50% → 75% → 100% の残存率を折れ線で見る。
- 見方: **特定区間で急落している箇所=離脱セクション**。例: 50%→75%で半減していたら、その位置のセクション(料金表や長文事例)が重い。急落セクションを特定→「短縮・図解化・順序入替」のいずれかを翌週実施。
- 判断基準の目安: 50%到達60%以上 / 100%到達25%以上なら健全。CTAクリックが少ないのに100%到達が高い場合は「読まれているが刺さっていない」=オファーの問題。

### 3-4. 週次でSlackに残すもの

リライトキュー更新内容 / 改題した記事 / CTA・スクロールの気づき1行 — を週次スレッドに記録(月次レビューの材料)。

## 4. 月次運用(半日)

### 4-1. ヒーローコピー A/Bテスト運用

**運用方式**: 静的HTML+低トラフィック前提のため、同時出し分けではなく**2週間交互のカレンダーテスト**を推奨(月前半=A案、後半=B案)。判定指標は `ヒーローCTAクリック率(cta_click{hero_*} ÷ セッション)` と `lead_capture ÷ セッション`。各案のセッションが最低500に届かない月は判定を持ち越す(統計的に差が言えないため)。

**現行案(チャンピオン)**
> AI導入補助金で、導入費を最大470万円圧縮する。

**挑戦者案1(不安払拭・丸投げ型)** — ペルソナの「ITは苦手・騙されるのが怖い」に対応
> 申請は、丸ごとお任せください。
> 採択率90%以上のプロが、AI導入費を最大470万円分軽くします。

**挑戦者案2(自分ごと化・課題起点型)** — 「エクセル管理の限界」から入る
> そのエクセル業務、補助金でAIに変えませんか。
> 上限350万円+先着20社は最大120万円OFF。

テスト順序: まず現行案 vs 挑戦者案1(訴求軸: ベネフィット直球 vs 不安払拭)。勝者 vs 挑戦者案2(訴求軸: 金額 vs 課題共感)。**1テスト=ヒーローコピーのみ変更**、他要素(CTA文言・画像)は固定する。結果と学び(どの訴求軸が刺さるか)を「A/Bテストログ」シートに必ず記録。

※数値表現の注意(景表法): 「最大470万円」は補助上限350万円+採択者限定割引120万円の合算である旨の注記をヒーロー近傍に必ず併記し続けること。

### 4-2. 診断完了率とゲート離脱率の改善チェックリスト

計測定義:
- 診断開始数: `cta_click {cta_id: shindan_start}`(LP側の診断開始CTA)
- 診断完了率 = `diagnosis_complete ÷ 診断開始数`(目標70%以上)
- ゲート離脱率 = 8問回答後、連絡先入力(ゲート)で離脱した割合 ≒ `1 −(diagnosis_complete ÷ 8問目到達数)`。8問目到達イベントがない場合は「診断開始 − 診断完了」を近似値として使う(目標: ゲート離脱40%未満)

チェックリスト(毎月、上から順に確認):
- [ ] 設問数は8問のままか(追加していないか。1問増は完了率を確実に下げる)
- [ ] 進捗表示(3/8 など)が機能しているか
- [ ] ゲート直前に「結果はこの画面ですぐ表示」「営業電話はいたしません」の2文があるか(戦略設計書 §3: 警戒解除装置)
- [ ] ゲートの必須項目は名前+メールの2つだけか(会社名は任意か)
- [ ] スマホで診断→入力→結果まで自分で通し、引っかかる箇所がないか(月1回の実機確認)
- [ ] 診断完了メールの到達確認(迷惑メール行きになっていないか)
- [ ] grade別の相談移行率(`diagnosis_complete {grade}` 別のCalendly予約数)を確認し、S/A判定者への文面を強化

### 4-3. キーワードマトリクス棚卸し

[戦略設計書.md](../../戦略設計書.md) §2 の100本マトリクスを月1で棚卸し:

1. 公開済み記事に GSC の実績(表示/クリック/順位)を転記
2. 優先度の入替え:
   - 順位が付き始めたB/A記事 → **Sに昇格**(§5の優先ルール)
   - 3ヶ月表示ゼロのS記事 → 検索意図を再調査し、B降格 or キーワード差替え
   - GSCで発見した「マトリクスにない実クエリ」→ 新規行として追加(実需要の証拠付きなので優先度S/A)
3. 翌月の執筆計画(週2本目安)をこの棚卸し結果から決める

## 5. 優先順位ルール: 「順位が付き始めた記事の強化 > 新規記事 > LPの微調整」

限られた工数の配分は毎週このフローで機械的に決める:

```
Q1. GSCに順位11〜50位で表示回数が伸びている記事があるか?
 ├─ YES → 【最優先】その記事のリライト・内部リンク強化に工数を使う
 │        (理由: Googleが既に評価し始めた記事は、追い風に帆を張るだけで伸びる。
 │         投資対効果が最も高い)
 └─ NO ↓
Q2. 今月の新規記事ノルマ(S優先度・週2本目安)は消化できているか?
 ├─ NO → 【次点】新規記事を書く(弾がなければ順位も付かない)
 └─ YES ↓
Q3. LPに数値上の明確な課題(CTA率低下・離脱急増・A/Bテスト実施中)があるか?
 ├─ YES → LPの微調整を行う(ただし1度に1要素・計測期間2週間を厳守)
 └─ NO → LPは触らない(データなき変更は計測を汚すだけ)
```

例外(フローより優先): 主要3KWの順位急落(5位以上)/ CV停止などの障害対応 / 補助金公募スケジュール発表に伴う日付・締切の即時更新。
